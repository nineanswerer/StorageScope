## 整改结果

### SS-SAFETY-01：Windows 保护路径大小写

- 后端保护比较统一转为小写，前端选择层采用相同口径。
- 参考目录与排除目录继续保护自身、后代和祖先目标。
- Rust 与前端模型测试覆盖 `cache/originals` 和输入 `Cache/Originals`。
- 真实窗口以实际目录 `Backups`、输入 `backUPS` 验证参考保护生效。

### SS-SAFETY-02：硬链接释放量

- 合并前读取旧实体的分配大小和链接数。
- 旧实体仍有其他硬链接时，本项释放记为 0。
- 最后一个链接移除时，计入旧实体分配大小。
- 测试与真实窗口均覆盖两种计量结果及其他硬链接的内容保留。

### SS-SAFETY-03：重复内容最终确认

- xxHash64 用于候选筛选和变化复核。
- 分析判重、硬链接合并与回收站执行前均进行逐字节比较。
- 同哈希不同内容的整组候选撤下，避免组标识冲突。
- 重复组相关回收站操作先完成组内内容确认，再处理任何目标。
- 锚点变化、缺失或无法读取时，整批回收站计划中止。

### SS-SAFETY-04：合并范围

- 移除“合并全部重复组”。
- 只有当前保留项以外的所有副本均被勾选，才允许合并该组。
- 部分选择的组不会随其他组进入执行。
- 路径搜索、类型筛选和前 50 项展示只影响显示，不改变执行范围。
- 确认框列出实际组数、副本数、路径预览和硬链接影响。
- 真实窗口先筛选并完整勾选 A 组，B 组保持独立实体；再单独勾选 B 组完成第二次合并。

### SS-SAFETY-05：备份命名目录

- `backup`、`backups` 已移出默认清理候选。
- 集成测试覆盖 `backup`、`backups`、`Backup`。
- 实景样本中的 `backup/only-copy.txt` 未进入清理建议。

## 真实窗口验收

调试窗口和 v0.2.0 release 窗口分别执行同一套隔离样本。

### 回收站与快照

样本包含 9 个文件，其中 `backup/only-copy.txt` 只用于验证默认规则边界。分析结果为 8 个候选项：4 个大文件、3 个缓存命名目录和 1 个重复组。

已验证：

1. `backUPS` 能保护实际 `Backups` 目录；重复组锚点切换到受保护路径。
2. 部分选择的重复组禁用合并按钮。
3. 参考目录与排除目录从选择集合和体积统计中移除。
4. 分析后向 `cache` 新增文件，执行时该目录完整跳过。
5. 另外 2 个未变化文件进入回收站，界面记录待清空 7.0 MiB。
6. 受保护的 `Backups/app-copy.bin` 与 `Downloads/setup.exe` 保留。
7. 执行后保存结果快照，并与分析基准完成差异比较。

### 选组合并与硬链接

A 组有两个独立实体路径参与候选，其中冗余副本还有 `extra-link.bin` 作为旧实体的另一个链接。B 组是两个普通独立文件。

已验证：

1. 空选择禁用合并。
2. 用路径筛选只显示 A 组，完整勾选后仅提交 A 组。
3. A 组两个候选路径合并后共享实体，`extra-link.bin` 保留旧实体，已核实释放为 0 B。
4. 未勾选的 B 组两个路径仍是不同实体。
5. 单独完整勾选 B 组后合并，已核实释放 3.0 MiB。
6. 两轮结束后所有路径内容正确，无 `.ss-merge-bak` 残留，重复候选为 0 组。

回收站样本会进入本机回收站；验收未清空回收站。所有清理目标均为专门创建的测试文件。
