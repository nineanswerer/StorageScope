# Beta 发布检查清单

适用于 `0.3.0-beta.2` 及后续 Beta。每个 Release 都按实际结果填写，不把本机记录扩展为多设备结论。

## 1. 源码与自动化

- [ ] 桌面版本在 `Cargo.toml`、`Cargo.lock`、`tauri.conf.json` 中一致。
- [ ] `git diff --check` 通过，只包含本次发布文件。
- [ ] Rust 核心格式、Clippy `-D warnings` 与工作区测试通过。
- [ ] 桌面包格式、Clippy `-D warnings` 与测试通过。
- [ ] 前端 lint、`test:model` 和生产构建通过。
- [ ] `main` 已推送，GitHub Actions 对应提交成功。

## 2. 构建与签名

- [ ] 使用同一前端生产构建生成 NSIS。
- [ ] 免安装 ZIP 使用同一 release 主程序，并包含用户说明与第三方声明。
- [ ] 记录主程序、安装包和 ZIP 的字节数与 SHA-256。
- [ ] 有代码签名证书时，按[签名流程](SIGNING.md)签署并用 `signtool verify /pa` 验证。
- [ ] 没有证书时明确标记“未签名”，不得把自签名或时间戳当作有效发布签名。

当前 `0.3.0-beta.2` 的 Authenticode 签署受代码签名证书缺失阻塞，发布资产按未签名状态说明。

## 3. 本机验收

- [ ] 在隔离路径安装 NSIS，执行启动、扫描、取消、结构视图、清理复核、回收站结果、快照比较和诊断导出。
- [ ] 覆盖安装保留快照，卸载移除程序和快捷方式并保留用户数据，重装可读取旧快照。
- [ ] 从已发布旧版升级，快照保留。
- [ ] 免安装版解压运行、移动目录和替换升级通过，无附加命令行窗口。
- [ ] 旧版能够发现新 pre-release，并打开正确发布页。
- [ ] 测试使用合成目录，结束后关闭所有测试应用和临时服务。

## 4. 发布与远程核验

- [ ] 创建 `prerelease: true` 的 GitHub Release，标签与桌面版本一致。
- [ ] 上传 NSIS 和免安装 ZIP，发布说明包含版本、主要变化、验收范围、已知限制和 SHA-256。
- [ ] 重新下载远程资产，核对文件名、字节数和 SHA-256 与本地一致。
- [ ] Release 链接指向正确标签，安装版和免安装版均可公开下载。
- [ ] README、用户指南、测试指南和验收记录反映最终实际状态。

## 5. 外部 Beta 与剩余风险

- [ ] 提供[测试指南](BETA_TESTING.md)、Issue 模板和安全反馈入口。
- [ ] 区分本机结果、外部测试结果与未执行项目。
- [ ] 保留 UAC、其他 Windows 设备、文件系统、网络目录和真人测试的独立记录。
- [ ] 未达到后续稳定版标准前，不发布 v1.0 或宣称普遍兼容。
