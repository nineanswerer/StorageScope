# StorageScope 用户指南

当前版本：`0.3.0-beta.2`，面向 Windows x64 的外部 Beta 测试。

## 1. 安装与启动

### NSIS 安装版

1. 从对应 GitHub pre-release 下载 `StorageScope_0.3.0-beta.2_x64-setup.exe`。
2. 对照 Release 中公布的 SHA-256。PowerShell 可运行 `Get-FileHash -Algorithm SHA256 <文件路径>`。
3. 启动安装程序，选择安装位置并创建快捷方式。
4. 从快捷方式或安装目录启动 StorageScope。

当前安装包未配置 Authenticode 代码签名，Windows 可能显示未知发布者。哈希不一致时不要运行文件。

### 免安装版

1. 下载 `StorageScope_0.3.0-beta.2_x64-portable.zip` 并核对 SHA-256。
2. 解压后运行 `StorageScope.exe`。程序使用用户应用数据目录保存快照和诊断日志，数据位置以“快照与趋势”页面显示的数据库路径为准。
3. 替换升级时先退出程序，再保留原数据目录并用新文件替换程序文件。

两种形态都需要可用的 Microsoft Edge WebView2 Runtime。程序启动时不应出现附加命令行窗口。

## 2. 扫描与结构视图

1. 在“01 扫描目录”输入目录路径，或使用“选择目录”。首次测试请选择专门创建的合成目录或数据副本。
2. 点击“开始扫描”。扫描读取目录项和元数据，不修改文件内容。
3. 需要停止时点击“取消扫描”。取消结果标记为不完整，停留在扫描页，也不能作为有效快照入库。
4. 完整扫描后进入“02 目录结构”。列表适合精确查找，层级图用于比较占用，3D 树用于探索父子关系。
5. 3D 视图中拖动旋转、滚轮缩放，并通过节点下钻。列表与导出功能保留精确数据。

目录联接、符号链接等重解析点默认跳过并计入异常，避免越界或目录环。扫描出现异常时，相关统计可能不完整。

## 3. 快照与差异比较

- “03 快照与趋势”扫描并保存目录的文件清单、大小和目录结构。
- “04 差异比较”比较同一根目录的两个有效快照，展示新增、删除、增长、缩减和目录净变化。
- 快照保存的是元数据，不复制文件内容，因此不能用快照恢复被删除的文件。
- 自动快照沿用当前目录和数据库路径；取消或失败的扫描不会生成有效趋势记录。

## 4. 清理建议与执行

1. 在“05 清理建议”开始分析。缓存目录名称只是人工复核线索，大文件与重复文件也需要自行判断用途。
2. 设置参考目录和排除目录。参考内容用于查重，同时受到保护；排除目录及其相关祖先目标不会进入执行范围。
3. 逐项勾选目标，复核执行摘要和三种空间口径：
   - **候选逻辑大小**：所选文件或目录的逻辑大小，用于估计处理范围。
   - **待清空回收站大小**：成功移入回收站的逻辑大小，仍需自行清空回收站后才可能转化为卷可用空间。
   - **已核实分配空间释放**：重复文件合并后，按硬链接和实际文件实体核实的变化。
4. 执行前应用重新检查路径、目录清单、大小、修改时间和可获取的文件实体身份。发生变化或无法确认的目标会跳过。
5. 执行后检查逐项结果。只有部分成功时，界面会保留已变化候选的撤下和未执行项的结果，不会把全部目标记为成功。

回收站操作可通过 Windows 回收站还原。清空回收站是独立操作，StorageScope 不会自动清空。

## 5. 重复文件合并

全文哈希用于筛选，逐字节比较用于最终判等。只有完整勾选冗余副本的组可以合并，每组至少保留一个路径。

成功合并后，冗余路径会指向同一文件实体。以后通过任一硬链接修改内容，其他链接看到的内容也会变化。合并前请保留独立备份，并确认这种共享实体的行为适合当前数据。

应用在合并前写入恢复信息。进程异常中断后，重新扫描或合并同一根目录时会先核对备份并恢复原路径，再允许重试。

## 6. 更新与诊断

“03 快照与趋势 → 检查更新”手动查询 GitHub Release。应用只比较版本并打开发布页，下载、核对和安装由用户完成；不会自动替换程序。

“导出诊断”生成 JSON，包含版本、操作系统、架构和最近操作事件。扫描根和数据库路径使用 `$PATH_N` 占位。分享前仍应打开文件检查，确认没有需要保留的内容。

故障处理见[故障排查](TROUBLESHOOTING.md)，安全与恢复细节见[安全边界与恢复](SAFETY_AND_RECOVERY.md)，外部测试步骤见[Beta 测试指南](BETA_TESTING.md)。
