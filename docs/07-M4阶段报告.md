## 2．设计

- **映射规则**：顶级目录 = 街区（每街区一个色系，黄金角散布色相），子目录 = 楼，楼高 = `28 × log10(1 + 大小MB)` 米（对数刻度，1 GB ≈ 22 楼高米，60 GB 的 PCL2 ≈ 111 m）；目录本级直属文件生成低矮去饱和的"广场楼"。
- **布局**：slice-and-dice 树图平铺到 220×220 m 城市平面；街区间留 6 m 道路，楼间留 0.7 m 缝；行高 = 行总面积/城市边长，面积精确铺满（实测 505 栋仅 6 栋微越界，来自最小宽度钳制）。
- **性能**：全部楼体一个 InstancedMesh（1 次绘制调用），505 实例；标签为 CanvasTexture Sprite（前 8 大街区）。远低于 300 draw 预算。
- **发光感**：`onBeforeCompile` 让 instanceColor 同时驱动漫反射与自发光——全息楼体效果。

## 3．验证

- Edit3D 版在 Work 浏览器中实际运行验证：场景图完整（505 实例 / 16 标签 / 材质全部命名 / 雾生效）、WebGL 硬件渲染（RTX 4060）、相机巡游 4 镜头绝对时间采样确定（seek 4→1→4 帧一致）、布局无 NaN；
- 修复的布局缺陷：初版行打包在末行最多溢出 1 个街区宽度（66 栋越界）→ 改为面积精确铺满后越界降至 6 栋（视觉无感）；
- 桌面端集成版随应用启动验证（用户操作路径：扫描 → 2. 目录结构 → "3D 城市视图"）。

## 4．如实记录的限制

- **Edit3D 内嵌预览握手在本机超时**（`SCENE_HANDSHAKE_TIMEOUT`，最小立方体场景同样复现，判定为客户端/插件平台问题，与场景代码无关；页面本身在浏览器中正常初始化、渲染）。因此 `storagescope-city` 的 review 保持 `pending`，未做像素级审查，编辑模式（参数面板/巡游导出视频）未在内嵌环境验证。该工程可用 `npm run dev` 独立打开使用。
- 桌面端 3D 视图是简化版（无夜空天空盒、无巡游），换的是零额外服务、随扫随看。
- Blender 未安装；本作全部元素为参数化生成几何，按路由规则本就归 Three.js，无影响。

# 增补二：3D 立体树视图（用户验收通过）

## 迭代经过

M4 的视图探索经历了三轮：3D 数据城市（用户评：好看但对"找空间占用"没有直接帮助）→ 旭日图/冰柱图（仍是平面图表，非用户所想的"线性树"）→ **3D 立体树（球树/balloon 布局）**，即立体思维导图形态：球 = 目录、连线 = 从属关系。用户确认"功能可以了"。

## 实现要点（`ui/src/Tree3DView.tsx`）

- **布局**：根在中心，每层一圈环（半径间隔 42），逐层下倾 9 形成锥形轮廓；子节点在父节点扇形楔内按体积占比分配角度。
- **剪枝**：每节点最多展开 8 个最大子目录，其余聚合为灰色"…其他 N 项"叶子；深度上限 6，节点总预算 900。
- **渲染**：节点 = 单个 InstancedMesh 球（半径 ∝ log 体积，instanceColor 驱动自发光）；边 = 单个 LineSegments；顶层标签 = CanvasTexture Sprite。
- **交互**：OrbitControls 缓慢自转（交互即停、停手 3 秒恢复）；raycaster 悬停显示 tooltip（名称/体积/文件数/折叠数）；点击有子节点的球下钻为新的根，面包屑返回。

## 验证

- 前端 `tsc -b && vite build` 通过；MSVC 桌面端重建启动，用户扫描 D:\mc 实测后确认功能可用。
- 视图按钮区收敛为：列表 / 层级图 / 3D 树（城市按钮已按用户反馈移除，CityView 代码保留备用）。
