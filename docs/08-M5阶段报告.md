# M5 阶段报告：清理执行（移入系统回收站）

## 1．目标与结果

M3 的清理建议只能"看"，本阶段补上"做"：勾选分析结果中的缓存目录与重复文件副本，一键移入 Windows 系统回收站，形成"扫描 → 分析 → 清理"闭环。用户在测试目录（假缓存 4 MB + 3 份相同文件）实测通过。

## 2．实现

| 层 | 内容 | 位置 |
|---|---|---|
| 核心库 | `cleanup::move_to_trash`：逐条移入回收站，逐条记录成败，拒绝空路径/根目录/不存在路径 | `core/src/cleanup.rs` |
| 桌面命令 | `move_to_trash(root, rel_paths)`：后端拼接绝对路径，canonicalize 后强制校验目标仍在扫描根目录内（防 `..` 逃逸），任一无法解析即整体中止 | `apps/desktop/src-tauri/src/lib.rs` |
| UI | 缓存表逐行勾选；重复组单勾选 = 删除第一份以外全部副本；按钮实时显示已选项数与合计大小；确认弹窗；执行后成功条目即时从列表移除、失败逐条列明 | `ui/src/App.tsx` |

依赖：新增 `trash = "5"`（Windows 走 Shell 回收站 API，与资源管理器删除行为一致，可从回收站还原）。

## 3．安全设计

- **可恢复**：只进回收站，不做永久删除；
- **路径约束**：所有删除目标必须 canonicalize 后位于扫描根目录内；
- **保留策略**：重复文件组始终保留第一份；
- **失败隔离**：单条失败不影响其余，全部失败原因可见。

## 4．验证

- 新增 2 个单元测试：根目录/不存在路径拒绝；真实文件移入回收站后原位消失。全套 14/14 通过。
- 前端 tsc + vite 构建通过；MSVC 桌面端重建启动；用户测试目录端到端验收通过。

## 5．已知边界

- 回收站在跨盘移动大目录时实际是"移动"操作，耗时与体积相关；当前为同步执行，大批量清理时 UI 会等待（后续可改异步 + 进度）。
- 分析结果基于清理前的扫描；清理后建议重新扫描刷新统计。
