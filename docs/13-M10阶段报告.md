# M10 阶段报告：空间合并（硬链接去重）——差异化核心功能

## 1．定位

回应"功能太常规、没有存在必要"的批评：WizTree/TreeSize 都能找重复文件，但它们只能让你**删**。StorageScope 选择**合并**：把内容完全相同的 N 份文件合并为 NTFS 硬链接——磁盘上只存一份实体，**每个路径都保留、程序照常运行、空间真实释放**。对 Minecraft 多整合包共享 mod jar（D:\mc 重复冗余的主要来源）是零风险解法。

## 2．安全模型（与删除完全不同的风险等级）

- **执行前重新校验**：分析后文件可能已变，合并前对锚点与副本重新计算全文 xxHash64，不一致即跳过（`skipped_changed`）；
- **事务式合并**：副本改名备份（`.ss-merge-bak`）→ 建立硬链接 → 删除备份；任一步失败自动回滚到原状；
- **路径逃逸防护**：桌面命令对全组成员 canonicalize 并强制限定在扫描根目录内；
- 单条失败不影响其余，全部结果逐条可见。

## 3．实现

| 层 | 内容 | 位置 |
|---|---|---|
| 核心 | `dedup::merge_duplicates` + `merge_one`（备份/链接/回滚）；`rules::hash_file_for_merge` 复用全文哈希 | `core/src/dedup.rs`、`rules.rs` |
| 桌面 | `merge_duplicates` 命令（异步 + merge-progress 事件 + 路径校验） | `apps/desktop/src-tauri/src/lib.rs` |
| UI | 重复文件组区"空间合并"按钮：显示预计释放量、确认弹窗说明、进度、完成后按实际合并结果更新组列表 | `ui/src/App.tsx` |

## 4．验证

- 新增 2 个单元测试：①真实合并后两路径同实体（改锚点副本同步可见）、无备份残留、无关文件不受影响；②分析后内容变化的副本被跳过且原样保留。全套 16/16 通过。
- 前端构建通过；MSVC 桌面端重建启动。建议用户先在 test-junk（3 份相同假照片）实测，再到 D:\mc 执行。
