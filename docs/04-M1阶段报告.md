## 2．已验证能力

### 2.1 统计正确性（黄金测试）

`golden_stats_match_reference`：用一段刻意独立的 `std::fs` 朴素递归遍历作为参照实现，与扫描器结果逐项比对：

- 标准数据集：115 个文件、37 个目录、3.9 KB，三方（生成器清单／参照遍历／扫描器）数字完全一致；
- 覆盖场景：单文件、空目录、10 层深目录、20×5 宽目录、中文＋空格路径、emoji 路径、大小写相似文件名；
- 抽查聚合：宽目录 = 100 文件 / 3200 B，深目录链 = 10 文件 / 550 B，均与预期精确一致。

### 2.2 异常可报告

- `missing_root_reports_error_not_panic`：扫描不存在的根目录，错误进入清单，进程不 panic；
- 重解析点/符号链接默认不跟随，记录为 `SkippedReparsePoint` 条目；
- 元数据读取失败、目录读取失败各自分类记录，扫描不中断；
- 聚合树中受影响目录标记 `has_errors`，界面/输出提示"统计可能不完整"。

已知限制：Windows 下构造真实"无权限目录"需要 ACL 操作，本阶段未自动化覆盖，列入 M2 前补充项。

### 2.3 取消有效

- `cancellation_stops_scan_cleanly`：5 万文件数据集扫描中由另一线程置位取消标志，扫描干净停止，结果标记 `cancelled = true`，无错误条目、无 panic；
- CLI 支持 Ctrl+C 协作式取消（ctrlc 处理器置位同一标志），取消后不输出"看似完整"的结果；
- CLI 提供 `--cancel-after N` 演示/测试参数。注意：演示参数在进度回调（每 5000 文件）中触发，故 `--cancel-after 1000` 实际在第 5000 个文件处生效；核心库的取消标志是逐条目检查的。

## 3．首份性能基准

**测试环境**：联想拯救者 R7000（AMD Ryzen 7 7735H，16 GB 内存，RTX 4060）；Windows 10 22H2（10.0.19045.6093）；Rust 1.99.1 stable（x86_64-pc-windows-gnu，winlibs MinGW-w64 GCC 16.2.0）；发布版（release）构建。

| 基准 | 规模 | 耗时 | 说明 |
|---|---|---|---|
| 合成大目录首次扫描 | 50,000 文件 / 101 目录 / 89.5 MB | 4,776 ms | 缓存状态未控制 |
| 合成大目录复扫① | 同上 | 4,149 ms | 热缓存 |
| 合成大目录复扫② | 同上 | 3,942 ms | 热缓存 |
| 真实目录（mingw64 工具链） | 11,874 文件 / 408 目录 / 923.6 MB | 1,762 ms | 真实项目目录 |

观察：吞吐约 1 万文件/秒量级，瓶颈疑似在逐文件元数据读取与 Windows  Defender 实时扫描，不在遍历逻辑本身；并行度与批量元数据读取是 M5 性能阶段的优化候选，M1 不做提前优化。

未记录项（如实说明）：峰值内存、快照体积（SQLite 快照属 M2 范围）、3D 帧率（M4 范围）。

## 4．发现并已修复的问题

1. **jwalk 会产出根目录条目**：初版测试按"扫描器不含根目录"编写，差一断言失败。已修正口径：扫描器结果含根目录自身（`rel_path = "."`）。
2. **根目录自引用导致聚合栈溢出**：`parent_of(".") == "."`，根目录进入目录集合后递归构建死循环。已修复：根目录不进入目录集合，由树构建逻辑单独处理。
