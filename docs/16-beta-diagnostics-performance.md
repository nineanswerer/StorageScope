# Beta 诊断与性能验收

## 诊断能力

桌面端把扫描、快照保存、快照比较、清理分析、回收站执行和重复文件合并写入本地 `operations.jsonl`。每条记录包含时间、应用版本、操作名称、操作编号、阶段和错误详情。阶段包括 `started`、`succeeded`、`failed`、`cancelled` 与 `interrupted`。

日志位于固定的用户应用数据目录。扫描根和数据库路径在错误文本中替换为 `$PATH_N`。日志达到 5 MiB 后轮转为 `operations.previous.jsonl`，当前与前一份日志合计最多导出最近 1,000 条事件。

用户可在“快照与趋势 → 导出诊断”主动生成 JSON。导出文件包含应用版本、操作系统、架构、事件和损坏日志行数。分享前仍应检查文件内容。

自动化测试构造包含“个人资料”的路径，确认原始日志与导出文件均只保留占位符。桌面操作互斥、路径边界和诊断脱敏共计 4 项桌面测试通过。

## 合成性能基准

基准日期：2026-11-02，本机时区。

| 项目 | 环境 |
| --- | --- |
| 操作系统 | Windows 10 Pro，10.0.19045 |
| 处理器 | AMD Ryzen 7 7735H，16 逻辑处理器 |
| 内存 | 16,312,721,408 B，约 15.2 GiB |
| 程序 | release 模式 `ss-cli` |
| 样本 | 200 个目录 × 500 个文件，共 100,000 个文件 |
| 样本逻辑大小 | 200,597,632 B，约 191.3 MiB |
| 运行次数 | 3 次；下表给出中位数及最小—最大范围 |
| 内存口径 | Windows `GetProcessMemoryInfo` 的 `PeakWorkingSetSize` |

每次运行先恢复相同的合成基线。扫描与取消后保存第一份快照，再新增一个文件、删除一个文件并将另一个文件扩大一倍，保存第二份快照并比较。

| 测量项 | 总耗时中位数（范围） | 峰值工作集中位数（范围） |
| --- | ---: | ---: |
| 完整扫描与结构聚合 | 578 ms（567—606） | 22,491,136 B（22,470,656—22,523,904） |
| 10,000 文件处取消 | 124 ms（116—135） | 6,549,504 B（6,545,408—6,582,272） |
| 第一次扫描并保存快照 | 806 ms（799—911） | 25,116,672 B（25,104,384—25,137,152） |
| 第二次扫描并保存快照 | 838 ms（745—856） | 25,063,424 B（25,059,328—25,088,000） |
| 两份快照比较 | 609 ms（564—662） | 57,651,200 B（57,622,528—57,733,120） |

扫描器内部计时中位数为 366 ms（365—381）；取消内部计时中位数为 32 ms（30—34）。进程总耗时还包含启动、统计或序列化等工作。取消结果停在 10,000 个文件；每轮差异均识别 1 个新增、1 个删除和 1 个增长文件，所有进程退出码为 0。

这些结果反映本机、合成小文件和当时磁盘缓存状态。桌面窗口响应、3D 渲染帧率和其他设备性能需在对应环境单独测量。本组数据未触发额外的核心算法改写。

完整数值与各轮来源见 [performance-100k.json](performance-100k.json)。`scripts/benchmark.ps1` 可对已生成的合成目录重复测量；脚本只修改该合成目录中的三个基准文件及指定输出目录。
