# 安全边界与恢复

## 文件操作边界

- 清理目标限定在已规范化的扫描根目录内，扫描根目录本身不能作为回收站目标。
- Windows 系统关键目录、参考目录、排除目录及其保护边界在前端选择层和 Rust 执行层分别检查。
- 目录联接、符号链接和其他重解析点默认不跟随。通过链接越出扫描根的目标会被拒绝。
- 缓存目录名称只生成复核建议，不代表内容可以无条件删除。
- 重复文件必须保持完整选组，每组至少保留一个路径；哈希相同后仍需逐字节确认。
- 执行前再次核对扫描基线。文件、目录或锚点发生变化时，对应操作跳过并给出原因。

这些检查降低误操作风险，但不能替代数据备份。外部测试先使用合成目录，再使用有副本的非关键数据。

## 空间口径

逻辑文件大小、NTFS 分配大小和卷可用空间是不同指标。移入回收站后，文件仍可能占用卷空间；重复文件仍有其他硬链接时，删除一个链接也可能没有可核实的分配空间释放。

界面分别呈现候选逻辑大小、待清空回收站大小和已核实分配空间释放。卷余量、回收站策略和不同文件系统的实际行为需要在对应环境单独测量。

## 从回收站恢复

1. 打开 Windows 回收站，核对项目名称、原位置和删除时间。
2. 选择需要恢复的项目并执行“还原”。
3. 回到 StorageScope 重新扫描原目录，再生成新的清理分析。
4. 如果项目已被跳过或路径已经变化，以新的执行前复核结果为准。

清空回收站后，本应用无法通过这些记录恢复文件。快照也不包含文件内容。

## 合并中断恢复

重复文件合并先建立备份和恢复记录，再替换目标路径。进程异常退出后，下次扫描或合并同一根目录时会执行恢复检查：核对备份内容，恢复原路径，并报告恢复消息。

中断后不要手动删除应用生成的备份或恢复记录，也不要把同名新文件放入原目标路径。先重新打开应用并扫描该根目录，确认恢复结果后再继续操作。

成功完成的合并没有回收站撤销步骤。需要独立副本时，应从事先创建的外部备份恢复。

## 已验证与未覆盖范围

本机自动化和隔离窗口验收覆盖路径逃逸、完整选组、Windows 大小写保护、目录变化、文件占用、权限不足、长路径、中文路径、目录联接、硬链接、中途失败和真实进程中断恢复。详细结果见[发布安全审查](15-release-safety-audit.md)。

其他 Windows 设备、UAC 提权场景、网络驱动器、可移动介质、更多文件系统、第三方安全软件组合和真人测试仍需要独立验证。当前安装包未签名，更新流程采用手动下载和安装。
