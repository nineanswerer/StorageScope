## 3．环境记录

- 桌面端改用 MSVC 工具链构建（`stable-x86_64-pc-windows-msvc`）：VS Build Tools 2022（MSVC 14.44 + Win SDK 10.0.26100）已安装；Tauri 官方要求 MSVC，GNU 工具链仅用于核心库与 CLI；
- WebView2 注意事项：短时间内反复启动调试实例可能报 `0x800700AA`（陈旧用户数据目录锁），等待片刻或为每次启动指定独立 `WEBVIEW2_USER_DATA_FOLDER` 即可。

## 4．真实场景暴露并已修复的问题

1. **jwalk 活锁**（详见 [04-M1阶段报告](04-M1阶段报告.md) §6）：扫描库在 30 万级真实目录上活锁。已移除 jwalk，改用 `std::fs::read_dir` 迭代式工作栈（commit `e3503c1`）。
2. **聚合统计 O(n²) 导致"扫描完成后卡死"**：`stats::aggregate` 建树时每节点全表扫描目录集合，39,738 目录 ≈ 8 亿次比较；release 下约 4 分钟、debug 桌面端下以小时计，表现为进度停在最后刻度、CPU 占满单核。已改为一次性构建父子邻接表，复杂度 O(n)（commit `7f57e71`）。修复后 release CLI 实测 **扫描 + 聚合全程 4.1 秒**（热缓存）。

教训：M1 的合成基准（5 万文件 / 101 目录）目录数太少，掩盖了目录数平方项。后续阶段的合成基准必须同时拉满"文件数"与"目录数"两个维度。
