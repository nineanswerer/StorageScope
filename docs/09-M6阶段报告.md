# M6 阶段报告：性能优化（并行哈希 + 清理异步化）

## 1．结果一览

| 指标 | M5（串行） | M6（并行） | 提升 |
|---|---|---|---|
| D:\mc 完整分析（30.8 万文件，扫描 + 缓存 + 大文件 + 重复检测） | 约 62 秒 | **18.8 秒** | **3.3×** |
| 分析结果正确性 | 基准 | 逐组一致（可回收 17.6 GB、哈希读取 26.7 GB、0 错误） | 无回归 |

## 2．并行哈希（`core/src/rules.rs`）

- 两阶段检测（64 KiB 头部指纹 → 全文 xxHash64）全部并行化，**8 线程工作池**，纯标准库 `thread::scope`，无新依赖。
- 负载均衡用原子索引窃取（`fetch_add`）：线程各自领下一个文件，避免"一个线程被大文件拖住、其他线程干等"。
- 分组键从"大小 → 指纹"嵌套循环改为扁平 `(大小, 指纹)` / `(大小, 全文哈希)` 哈希分组，语义与串行版完全等价。
- 进度回调加 `Send` 约束，原子计数 + 加锁回调（每 200 文件一次）；总进度口径改为"候选数 × 2"（含两个阶段）。
- `analyze` / `find_duplicates` 签名引入显式生命周期 `'a` 以满足 scoped 线程借用。

## 3．清理异步化（`apps/desktop/src-tauri/src/lib.rs`）

- `move_to_trash` 改为 `async` + `spawn_blocking`：大目录跨盘进回收站是物理移动，耗时与体积成正比，此前同步执行会冻结 UI，现在放入阻塞线程池，按钮显示"正在移入回收站…"，界面保持响应。

## 4．验证

- 全套 14/14 测试通过（含重复检测既有夹具，证明并行版结果与串行一致）。
- CLI 在 D:\mc 实测：18.8 秒完成，重复组明细与 M5 逐一相符。
- MSVC 桌面端重建启动。

## 5．后续可做（未纳入本阶段）

- 扫描阶段 IO 调度（当前扫描本身已是 std 迭代式，约占 18.8 秒中的 10 秒）；
- 哈希结果缓存（按 路径+大小+mtime 复用，二次分析接近秒出）；
- Release 构建的进一步优化（LTO、codegen-units）。
