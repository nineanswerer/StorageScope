# M9 阶段报告：打包发布（v0.1.0）

## 1．交付物

GitHub Release **v0.1.0**：https://github.com/nineanswerer/StorageScope/releases/tag/v0.1.0

| 文件 | 体积 | 说明 |
|---|---|---|
| StorageScope_0.1.0_x64-setup.exe | 2.92 MiB | NSIS 安装包（推荐） |
| StorageScope_0.1.0_x64_en-US.msi | 4.12 MiB | MSI 安装包 |

Windows 10/11 x64；运行依赖 WebView2（Win11 自带）。应用图标为程序生成的品牌图标（立体树 + 青蓝/橙配色，`app-icon.png`）。

## 2．打包配置

- `tauri.conf.json`：`bundle.active = true`，targets = msi + nsis，图标组接入 `tauri icon` 生成的全套图标。
- 构建命令：`RUSTUP_TOOLCHAIN=stable-x86_64-pc-windows-msvc cargo-tauri build --target x86_64-pc-windows-msvc`（Release + 双安装包一次产出）。
- tauri-cli 使用官方预编译二进制（`tools/tauri-cli/cargo-tauri.exe`，v2.12.4）。

## 3．环境坑（如实记录）

- 本机 node/npx 运行 @tauri-apps/cli 时参数被注入异常（报 `unrecognized subcommand 'C:\app\KIMI\Kimi.exe'`），JS 包装层不可用；改用 cargo install 编译过慢，最终采用官方预编译 cargo-tauri，问题绕过。
- tauri build 默认调用 GNU 工具链，需显式 `RUSTUP_TOOLCHAIN` 指向 MSVC 并传 `--target`。
- Release 上传通过 GitHub REST API + 本机 Git 凭据管理器完成（无 gh CLI）。
